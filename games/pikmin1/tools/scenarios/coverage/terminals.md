## 1. Flow map (what a scenario sits inside)

Section level (`GameFlow::softReset`, `src/plugPikiColin/gameflow.cpp:747-790`): `SECTION_NinLogo`, `Titles`, `MovSample`, `OnePlayer`, `PaniTest` (`GameCourseClearSection` on PAL only), `OgTest`. `mNextGameSectionID` / `mCurrGameSectionID`.

OnePlayer sub-section level (`OnePlayerSection::init`, `src/plugPikiColin/game.cpp:264-489`): `GameSetup`, `CardSelect`, `MapSelect`, `E3Tutorial`/`E3ForestDay1`/`E3ForestDay2` (E3 leftovers, re-queue `NewPikiGame`), `IntroGame`, `NewPikiGame`, `GameCourseClear` and `GameStageClear` (comments say never hit), `GameCredits` (E3 demo only), `GameExit`. Selected by `gameflow.mNextOnePlayerSectionID`.

Inside `NewPikiGame` the mode states (NPG): `IntroGameModeState` -> `RunningModeState` (`:1041`) -> `MessageModeState` (extinction / captain down, `:1494`) and/or `DayOverModeState` (`:1608`, phases 0-4 at `:1869 / :1969 / :2107 / :2177`) -> `QuittingGameModeState` (`postUpdate` sets `gameflow.mNextOnePlayerSectionID = mParentSection->mPendingOnePlayerSectionID`, then `gsys->softReset()`).

Ending types: `ENDING_None/Neutral/Happy` (`include/FlowController.h:14-16 (EndingType)`), `flowCont.mEndingType`. Written at `NPG:1134 (RunningModeState::update)` (neutral, sunset on Day 30 with >= 25 parts), `NPG:2071 (DayOverModeState::initialisePhaseTwo)` (neutral, phase two), `NPG:3418 (GameMovieInterface::parse)` (`MOVIECMD_SpecialDayEnd`, happy). Reset to `ENDING_None` in `gameSetup.cpp:188 (GameSetupSection::GameSetupSection)` and `movSample.cpp:428 (MovSampleSetupSection::update)`. Read by `GameExitSection::update` (`src/plugPikiColin/gameExit.cpp:32-47`): `!= None` goes to `SECTION_MovSample` with `mCurrIntroMovieID = mEndingType + MOV_ENDING_OFFSET (3)`, else `SECTION_Titles`. So the bad ending (no `mEndingType` write) returns to the title and neutral/happy go to the credits movie.

Game-end flag (`flowCont.mGameEndFlag`: `GAMEEND_None/PikminExtinction/NaviDown/Clear`, `include/FlowController.h:23-26`).

Constants: `MAX_DAYS = 30`, `MAX_UFO_PARTS = 30` (`include/GlobalGameOptions.h`), `happyEndable()` = `mRequiredUfoPartCount >= MIN_HAPPY_END_PARTS` (`PlayerState::happyEndable`, `src/plugPikiKando/playerState.cpp:328`). `MIN_HAPPY_END_PARTS` is a compile-time `#define` of 25 (`include/GlobalGameOptions.h:29`), not a parameter, so no disc file can override it. Ending selection, all in NPG: Day 30 sunset with `mCurrParts != 30` picks neutral when `happyEndable()` (25 or more required parts; the 5 optional parts Nova Blaster, Space Float, Massage Machine, Secret Safe and UV Lamp do not count, `PlayerState::getUfoParts`, `playerState.cpp:1170-1173`) and bad otherwise (`RunningModeState::update`, NPG:1131-1139; `DayOverModeState::initialisePhaseTwo`, NPG:2069; `initialisePhaseThree`, NPG:2132). Happy needs `mCurrParts == 30` (all parts, optional included) and is entered through `MOVIECMD_SpecialDayEnd` (NPG:3413) and `initialisePhaseOne` (NPG:1871). `gamePrms.bin` on the disc holds only clock values (`t00`/`t01`/`p00`-`p06`), `tekiAbility` and the title string, so it carries no ending override.

## 2. Harness facts that decide tiering

- Scenario ends the process on verdict. After a day-end completes, `QuittingGameModeState::postUpdate` calls `gsys->softReset()`, which builds `MapSelectSection` / `CardSelectSection` / `GameExitSection` -> `Titles`/`MovSample`. The stand-in tree has no map, file-select or title screens, so a scenario must pass or fail BEFORE that softReset. **Since #99 (2026-10-31)** the stand-in tree has the world map, title and file-select screens: `world_map_day_end` and `title_round_trip` run through them on pad input after the soft reset. Needed harness addition (effort S): a `pc_scenario_on_soft_reset()` hook (in `QuittingGameModeState::postUpdate` or at the top of `GameFlow::softReset`) that hands the scenario `mParentSection->mPendingOnePlayerSectionID`, `flowCont.mEndingType` and `gameflow.mNextGameSectionID`, and for scenarios lets it pass without building the next section. Every "next section" assertion below depends on this.
- `MoviePlayer::startMovie` (`src/plugPikiColin/moviePlayer.cpp:431`) looks the movie up in the static `movieTitles` table, so every DEMOID is known; the `.cin` for it is then opened by `MoviePlayer::initMovie` -> `new CinematicPlayer` -> `CinematicPlayer::loadCin` (`src/plugPikiColin/cinePlayer.cpp:133`). **A missing `.cin` is tolerated (verified):** `System::openFile` returns `nullptr` for a missing file (no ERROR), `loadCin` returns early, the movie has no scenes and `mTotalDuration == 0`, so `CinematicPlayer::update` reports it finished on its first update. Runs: `boot_smoke` on a stand-in tree clone without `demo60.cin` passes (the intro gate took 92 ticks instead of 15); `onion_skip` without `demo06.cin` does not crash but fails its own check (the Onion stays in `BootInit`, because the boot comes from the movie's Action keys); the captain-death run below passed through missing demo52/32/56/36/84 without an abort. The cost: a missing movie also drops every event key it carries (`MOVIECMD_*` Notify keys and `demoEventMgr` Action keys), and some chains depend on those keys (extinction, T04). Day-end phases wait on `gameflow.mMoviePlayer->mIsActive`, so a missing or tiny stand-in `.cin` advances each phase in a tick or two. Stand-in cinemas today: demo60, demo61, demo41, demo45, demo04, demo06, demo36 (the end-of-day results backdrop, added for `captain_death`), demo46, demo47 (the last two added for the `extinction` scenario), demo73 (the bad ending's escape, added for `extinction_day30`) (`tools/scenarios/standin-cinema.md`, confirmed in the generator output). Extinction is `DEMOID_Extinction` (46, `cinemas/demo46.cin`) and `ExtDayEnd` (translated per stage by `MoviePlayer::translateIndex` through `movie47table`: demo47 Impact Site, demo48 Forest, demo49 Cave and Last, demo50 Yakushima; the sandbox's `STAGE_TESTMAP` falls back to Impact Site, so demo47); demo46 and demo47 are now stand-ins (`standin-cinema.md`); demo48 to demo50 are not (demo60 is `Unk60Cat`, a different movie).
- Stand-in `.blo` screens exist for: `gameover`, `gameove2`, `pause`, `pause_ok`, `count`, `con01`, `sund`, `account`, `play09/10`, `play_day`, `tu_base`, `wait_char`, `tu_tx00/03/20/26/35/37_*` (`libs/nectar_assets/src/standin_ui.cpp`). Since added: the captain-death results chain (T06), the diary pages `re_j_00`, `re_n1_00`, `re_g_00` and the total-results window (`f_result`, `ufo_p`, `cha_sav2`, `ac_chui`; `standin-cinema.md`). NOT present: the other results diary pages (`re_a_00` ... in `src/plugPikiOgawa/ogResult.cpp:38 (zen::bloFile_Res_Table)+`), file-check/select screens, world map. Since added (2026-10-31, #99): the world map (`w_*.blo`, `pause_w`), the title (`press_s`, `m_select`, `m_selec2`, `m_menu_r`, `m_menu_b`, `option`) and file select (`data_b`, `data_i`, `data_m`, `data_pf`, `data_t1`, `data_t2`), and the Y menu (`cont_y`, `m_menu2`, `m_menu2m`, `cont_00`). - Existing scenarios cover none of the terminals except: `day30_clock` reaches `mIsDayEndActive` on Day 30 and then passes (clock/day-end start only). All scenarios boot through the intro gate (`IntroGameModeState` -> `RunningModeState`), so that transition is covered implicitly.
- `PC_SCENARIO` rejects `--mission-map`, `--vs-map`, `--coop*`, `--campaign`, `--input-replay` (`kRejectedFlags`, `pc_scenario.cpp`). Mission/VS terminals therefore cannot run as scenarios without lifting that rule; see the notes in the table. Co-op can since 2026-10-28: a scenario with `coop()` true gets two captains in split screen and a pad for the second (`coop_smoke`, `coop_look`; README, Co-op scenarios).
- Direct state manipulation available to a scenario: `gameflow.mWorldClock.setTime()/mCurrentDay` (used by `day30_clock`), `playerState` part counters (`mCurrParts`, `mRequiredUfoPartCount`), `pikiMgr` / `naviMgr` objects, `GameStat::*` counters, `gamecore->forceDayEnd()`, `flowCont.mGameEndFlag`.
