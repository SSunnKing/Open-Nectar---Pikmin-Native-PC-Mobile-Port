# RNG sequencing regression coverage implementation plan

Approved design: upstream expression-level tests plus separate fork gameplay evidence.

Goal: detect draw-order regressions in the eight #224 sites, and compare gameplay timing/state hashes on a recorded integration revision across macOS, Linux and Windows.

Architecture: compile source-extracted PC expressions inside a synthetic C++ context. Keep production expressions unchanged. An independent expected-output oracle and draw trace check both values and stream/range/count. Compile deliberate reordered variants and require specific assertion failures, never accepting compile failures as mutation detection. Fork CI retains full scenario logs, revision/compiler/build metadata, and asserts timing agreement alongside existing cross-OS hash comparison.

Tech stack: Python 3, C++17, GitHub Actions, existing CMake/CTest scenario runner.

1. Add source extraction, synthetic context and independent expected results for all eight sites; fail closed on missing/ambiguous source boundaries. Exercise attack weights and shooting-star conditional draw counts.
2. Run on Clang and GCC with -O0 and -O2. Reorder each site's first two draws and require the named runtime check to fail. Retain compiler/flags/revision/seeds and outputs.
3. Add upstream CI matrix and reproducible local command, limitations and helper/macro audit. Verify local Clang and available cross compilers.
4. On a separate fork branch, merge recorded upstream into current integration runner. Extend CI to retain provenance and compare calibrated throw-release timing at both rates, with comparator failure tests.
5. Run the fork matrix, retain links/results and update #250 with honest coverage and unresolved limitations. Open reviewable PRs; do not merge new code without review.
